## 1. 前提（ここを取り違えると設計を間違える）

| 項目 | 内容 |
|------|------|
| 目的 | 1回取得することではなく、**無人で毎日取り続けられる**状態を作ること |
| 対象 | サイトコントローラー **TL-リンカーン**（株式会社シーナッツ／ASP型・ブラウザで使う）、PMS **NEHOPS**（NEC） |
| API | **使えない前提**。公式APIは無し、または未確認のため当面は画面操作・HTTPリクエスト再現で取る |
| 実行場所 | **IP制限があるため、ホテルのネットワーク・その端末（Windows 1台）の上で動かす。** 自社サーバやクラウドから取得することはできない |
| 端末の制約 | ホテルの**業務用PC（フロント業務と共用）**。インストーラを使わない。管理者権限を前提にしない。レジストリやProgram Filesを汚さない |
| 絶対にやらないこと | **在庫・料金・プランの更新系操作**。TL-リンカーンは販売中の在庫と料金を握っており、誤操作がOTAの販売価格に反映される。読み取りとエクスポートの経路のみ通す |

## 2. すでに出来ているもの（作らなくてよい）

CSVが1本手に入った後の経路は実装・検証済み。**足りないのは「CSVを落とすところ」だけ。**

| 役割 | 場所 |

| CSV→実績への変換（Shift_JIS・泊数展開・キャンセル除外・ブッキングカーブ復元） | `backend/src/lib/csv.ts`、`backend/src/lib/reservationImport.ts` |
| 手元での列調査・取込CLI | `backend/src/scripts/importReservations.ts`（`pnpm --filter backend import:reservations`） |
| 端末からの送信（リトライ・ログ・処理済み移動） | `tools/field-test/Send-ReservationCsv.ps1` |
| 端末でのCSV調査・個人情報列の除去 | `tools/field-test/Inspect-ReservationCsv.ps1` |
| 取得（RPA）キットのひな形 | `tools/rpa/`（`export-tl.mjs`・`selectors.example.json`・`Setup-PortablePlaywright.ps1`・`Invoke-Pipeline.ps1`） |
| 欠損検知（前日分が無い／一定時間成功していない → アラート） | `backend/src/lib/importHealth.ts`、`backend/src/jobs/daily.ts` |
| 現地手順と記録欄 | `docs/現地テスト_2026-09-15_NEHOPS_TLリンカーン.md` |

### APIの形

```
POST /api/v1/import/reservations?hotelId=&source=tl-lincoln&asOf=YYYY-MM-DD&fileName=&dryRun=false
  Authorization: Bearer <accessToken>   Content-Type: text/csv
  本文: CSVそのもの（最大20MB / 文字コードは保存済みマッピングの設定に従う）
PUT  /api/v1/import/mapping     列マッピングの保存（取得元ごと）
GET  /api/v1/import/mapping     取得
GET  /api/v1/import/runs        取込履歴（成功・失敗の両方）
```

いずれも認証必須、hotelIdのテナント境界チェックあり、書き込み系は MANAGER 以上、監査ログを残す。
実績テーブルへの書き込みはすべて upsert なので、同じCSVを何度取り込んでも行は増えない。

## 3. 依頼したいこと（優先順）

### タスクA: HARからHTTPリクエスト再現スクリプトを作る（最優先・端末に何も足さない）

現地で取得した HAR を渡す。そこからログイン〜CSVエクスポートを **Windows標準のPowerShellだけ**で再現するスクリプトを作る。

- `Invoke-WebRequest -SessionVariable` でCookieを保持する。外部モジュールに依存しない
- 期間は引数で指定できるようにする（既定は直近30日）
- ダウンロードしたCSVは、ヘッダー行の列数と必須列を検証してから成功とする（エラーページのHTMLを掴んで成功にしない）
- 失敗は終了コード1で返し、1行1JSONでログに追記する（`tools/field-test/Send-ReservationCsv.ps1` と同じ流儀）
- 成功したら `tools/field-test/Send-ReservationCsv.ps1` に渡すか、同等のPOSTを行う
- **取得したCSVの中身や認証情報をログ・コミットに残さない**

### タスクB: `tools/rpa/export-tl.mjs` を実データで動く状態にする

現地で `codegen.cmd` を回して得た記録と、保存した画面HTMLを渡す。

- セレクタは `selectors.json` に書く。**コードにハードコードしない**（画面が毎月変わりうるため）
- 固定の待ち時間（`waitForTimeout`）を使わない。要素の出現とダウンロード完了を待つ
- 失敗時はスクリーンショットと trace を `out/` に残す（実装済みの枠を踏襲する）
- 期間指定の書式・ページング・「出力に時間がかかる場合の完了判定」を実物に合わせる

### タスクC: コンピュータ操作エージェント用の手順定義

画面操作を人ではなくエージェントに任せる場合の手順書（下の §5 のプロンプトをベースに、実物の画面名・ボタン名で具体化する）。
**定期実行の本番はこれではなくA/Bの決定論的スクリプトを使う**方針。エージェントは初回の探索と、壊れたときの原因調査に使う。

## 4. 守るルール（このリポジトリの規約）

`AGENTS.md` と `CLAUDE.md` が正。抜粋:

- 新しいAPIルートには `authenticate` を必ず適用。hotelIdを受けるルートには `requireHotelAccess`、変更系は `requireRole('ADMIN','MANAGER')` ＋ `writeAuditLog()`
- 入力は `backend/src/lib/validators.ts` の zod スキーマ＋`validate()` で検証。生の `req.body` / `req.query` を参照しない
- backend で `process.env` を直接参照しない（`src/lib/config.ts` の `config` を使う）
- Prismaクライアントの import は `src/services/` と `src/lib/` のみ
- 新しいPrismaモデルには `tenantId` ＋ tenantリレーション＋ `@@index([tenantId])`
- スキーマ変更は `prisma migrate dev` でマイグレーションを生成してコミットする（`db:push` は使わない）
- コミットは Conventional Commits ＋ 件名末尾に対応するIssue/タスクID（例 `feat(tools): ... (#6)`）
- コミット前に通すこと:

```bash
pnpm --filter './*' type-check && pnpm --filter './*' lint
pnpm --filter backend test
pnpm --filter backend build && pnpm --filter frontend build
```

## 5. コンピュータ操作エージェントへの指示（そのまま渡す用）

```
あなたはホテルの業務用Windows PC上で、ブラウザを操作してデータを取得する作業を行います。

対象: サイトコントローラー「TL-リンカーン」（ブラウザで使うASP型のサービス）
目的: 予約明細を直近1か月ぶんCSVでエクスポートし、操作手順と画面上の要素を記録すること

必ず守ること:
1. 参照とエクスポートのみ行う。在庫・料金・プラン・予約内容を変更する操作は一切しない。
   「更新」「登録」「反映」「送信」「削除」と書かれたボタンは押さない（CSV出力のためのボタンは除く）。
   判断に迷ったら操作を止めて、画面の状態を報告して指示を仰ぐ。
2. 認証情報を出力に含めない。パスワードをそのまま書き出さない。
3. スクリーンショットに宿泊者の氏名・連絡先が写る場合は、その旨を報告する。
4. ログイン画面のURLは指示されたものだけを使う（検索結果から別サイトへ入らない）。

手順:
1. 指定されたURLでログインする（認証情報は別途渡す）
2. 予約検索の画面を開く
3. 期間を「今日から30日前」〜「今日」に設定する
4. 検索し、CSVエクスポートを実行する
5. ダウンロードされたファイルのパス・ファイル名・サイズを報告する

報告に含めること（後で決定論的なスクリプトに書き換えるための材料）:
- クリックした要素の順番と、それぞれの表示名／種類（ボタン・リンク・タブ）
- 入力した項目名と入力値の書式（とくに日付の書式）
- 各画面のURL
- 待ちが発生した箇所と、完了が分かる目印（画面の文言・アイコン・ダウンロード通知）
- 途中で出たダイアログ・警告・エラーの文言（そのまま）
- 詰まった点、判断に迷った点
```

## 6. 渡す添付物と扱い

| 添付 | 用途 | 注意 |
|------|------|------|
| HAR（`Save all as HAR with content`） | タスクAの材料 | セッションCookie・トークン・宿泊者名が入る。**共有前に確認し、認証情報を除去する。リポジトリにコミットしない** |
| 画面のHTML（Ctrl+S または outerHTML） | タスクBのセレクタ | 同上 |
| codegen の記録・trace | タスクB | 同上 |
| 画面録画 | 手順の理解 | 画面に個人情報が写りうる |
| 予約明細CSVのサンプル | 列マッピング作成 | **氏名・連絡先の列を除いたもののみ**（確認事項A12） |

## 7. 完成の条件

1. 端末上でコマンド1本（またはタスクスケジューラの1タスク）から、人が触らずにCSV取得→取込API送信まで通る
2. 失敗時は終了コードとログで分かる。画面変更で壊れた場合も「黙って成功」しない
3. 同じ日に2回動かしても実績が二重計上されない（サーバ側がupsertなので、取得側は冪等性を壊さない作りであればよい）
4. 翌日も自動で動き、`GET /api/v1/import/runs` に2日連続の成功が残る
5. 取込が止まったら日次バッチのアラートで気づける（既存機能。有効であることを確認する）
