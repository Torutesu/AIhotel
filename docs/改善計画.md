# 改善計画（総点検 2026-09-11 の所見に基づく）

総点検で洗い出した所見を、実装順・担当領域・受け入れ条件つきのタスクに落としたもの。
各タスクの ID はコミット件名の末尾に付ける（例 `fix(backend): アクセストークンに type クレームを追加 (S-1)`）。

- 前提: AGENTS.md の必須ルール（認証／テナント分離／zod／監査ログ／`config` 経由の環境変数／マイグレーションのコミット）は全タスクに適用する。
- 検証: 各 Wave の終わりに `pnpm --filter './*' type-check` → `pnpm --filter './*' lint` → `pnpm --filter backend test` → 両ビルド → ローカル PostgreSQL での migrate/seed/API 疎通 → ブラウザ操作を通す。
- 方針の変更点（要確認）: **デモモードを opt-in（`NEXT_PUBLIC_DEMO_MODE=true` のときだけ有効）に変える**。既存のデモ環境（hotel-price.vercel.app）を維持するには Vercel の環境変数に `NEXT_PUBLIC_DEMO_MODE=true` を設定する必要がある。

## 依存関係の既知の残課題

`pnpm audit --prod` の high / critical は 0 件（CI の audit ジョブはこの水準をゲートにしている）。
残る 1 件は以下の理由で保留する。

| 深刻度 | パッケージ | 経路 | 保留理由 |
|---|---|---|---|
| moderate | `uuid` < 11.1.1 | `backend > exceljs > uuid@8` | 該当脆弱性は `v3/v5/v6` に `buf` を渡した場合のみ。exceljs は `v4()` しか呼ばないため影響しない。exceljs 4.4.0 が最新で上流の更新待ち |

`brace-expansion` / `deepmerge-ts` / `qs` / `body-parser` / `sharp` / `postcss` / `nanoid` は
ルート `package.json` の `pnpm.overrides` でパッチ版に固定している。上流が追随したら override を削除する。

### 実装中に追加で見つかり修正したもの

| 内容 | 影響 |
|---|---|
| `next.config.mjs` の `rewrites()` は転送先を `next build` 時に `routes-manifest.json` へ焼き込むため、実行時の `BACKEND_URL` が反映されない。コンテナを一度ビルドして環境ごとに差し替える運用（`docker/frontend.Dockerfile` の想定）では常にビルド時の値へ転送され、本番で500になる | `app/api/[...path]/route.ts` のルートハンドラに置き換え、毎リクエストで解決。PDF/Excel等のバイナリも中継 |
| フロントの未使用ファイル整理で `frontend/public/` が空になり、Dockerイメージの `COPY frontend/public` が失敗する状態だった | `.gitkeep` を置いてディレクトリを維持 |
| 開発環境で Prisma が全SQLをログ出力し他のログが埋もれる | `LOG_LEVEL=debug` 指定時のみに限定 |
| `express` 経由の `qs` / `body-parser`、`exceljs` 経由の `brace-expansion`、`prisma` 経由の `deepmerge-ts` に脆弱性 | `express` を 4.22.2 に更新し、残りは `pnpm.overrides` でパッチ版へ固定 |

`#41`〜`#57` および `#62`〜`#65` として起票されたレビュー所見を、上記 Wave A〜C に続けて解消した。

### ロール体系の変更（#62 — 最重要）

ADMIN がテナントを越えてデータを読めていた点について、**権限そのものを分離**した。

| ロール | 日本語表示 | tenantId | テナント越え | 想定利用者 |
|---|---|---|---|---|
| `PLATFORM_ADMIN` | 運営 | null | **可（唯一）** | サービス提供側。顧客には渡さない |
| `ADMIN` | 管理者 | 必須 | 不可 | 顧客テナントの管理者（テナント内で最上位） |
| `MANAGER` | マネージャー | 必須 | 不可 | 支配人・レベニューマネージャー |
| `OPERATOR` | オペレーター | 必須 | 不可 | 現場フロント |

- `requireHotelAccess` のロール早期 return は `PLATFORM_ADMIN` のみ。`ADMIN` は必ずテナント判定を通る
- `requireRole` は `PLATFORM_ADMIN` を全ロールの上位集合として扱う
- ユーザー登録の `tenantId` は**作成者のテナント**から導出する。他テナントのホテルIDを送っても
  「指定されたホテルが見つかりません」（400）で、そのホテルの存在は判別できない（#52）
- 併せて `PUT` / `DELETE /hotels/:id` に `requireHotelAccess` が無かった不備を修正（テナント管理者が
  他テナントのホテルを改名・論理削除できた）
- 日本語表示名の唯一の出所は `shared/types/index.ts` の `ROLE_LABELS`

**#49-4 の実装内容**

- 回転済みトークンは行を削除せず `revokedAt` を立てて残し、再提示を検知できるようにした
- 失効と新規発行を 1 トランザクションにまとめ、`revokedAt IS NULL` を条件にすることで
  同時リフレッシュでもトークンが二重発行されない（従来は削除と作成が別クエリで、
  その間に落ちると理由なくログアウトされていた）
- 猶予（10秒）を超えた再提示は盗用として当該ユーザーの全トークンを失効させ、
  監査ログ `TOKEN_REUSE_DETECTED` を残す。猶予内（複数タブの競合）は 401 のみで他端末を切らない
- リフレッシュトークンに `jti` を付与。従来は payload も iat も同一で、同じ秒に2回発行すると
  同一文字列になり `tokenHash` の一意制約違反で回転そのものが失敗していた
- 不正・期限切れ・アクセストークンの流用はすべて 401（従来は 500 で、クライアントが
  「再ログインが必要」を判別できなかった）
- 期限切れトークンの全体掃除を日次バッチに追加（従来はログインしたユーザーぶんのみ）

### #51-2（設定の永続化）の実装内容

- `UserPreference`（`tenantId` + リレーション + `@@index`、`(userId, hotelId)` で一意）を追加
- `GET` / `PUT /api/v1/preferences`。`authenticate` + zod `validate()` + `requireHotelAccess` + 監査ログ
- 書き込み対象は常にトークンのユーザー自身で、`userId` はリクエストから受け取らない。
  変更系だが `requireRole` は付けない（OPERATOR も自分の画面設定は変更できる必要があり、
  他者・他テナントのデータには一切触れないため）
- 設定タブ・ダッシュボードを localStorage から移行。ブラウザ保存が残るのはテーマ（next-themes）と
  サイドバー開閉のみで、いずれも端末ごとの表示の好み
