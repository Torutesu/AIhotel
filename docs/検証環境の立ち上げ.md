# 検証環境の立ち上げ（管理画面まで触れる環境）

今のデモサイト（https://a-ihotel-frontend.vercel.app）は画面だけで、バックエンドにつながっていない（サンプルデータのデモモード）。
運営の管理画面（テナント管理・トライアル管理）、IP 制限、データの保存を実際に使うには、バックエンドと DB を置いて画面とつなぐ。

本番のクラウドは #21 で決める。それまでの検証環境として、コンテナと DB をまとめて置ける Render を使う手順を示す（同じコンテナイメージなので、本番のクラウドにもそのまま移せる）。

## 1. Render にバックエンド・DB・定期ジョブを作る（約10分）

1. https://render.com でアカウントを作る（運営の共有メールアドレスで作る。個人のアカウントにしない）
2. ダッシュボードの **New → Blueprint** で GitHub の `Torutesu/AIhotel` を選ぶ（リポジトリ直下の `render.yaml` が読み込まれる）
3. `BOOTSTRAP_ADMIN_EMAIL` に運営アカウントのメールアドレスを入れて **Apply**
4. 次のものが作られる（2026-09 時点の目安: 合計で月 20 ドル前後）

   | 名前 | 内容 |
   |---|---|
   | `aihotel-db` | PostgreSQL 16（シンガポール） |
   | `aihotel-backend` | API サーバー。起動時にマイグレーションを適用する |
   | `aihotel-daily` | 日次バッチ（毎日 04:00 JST） |
   | `aihotel-competitor-prices` | 競合価格の取得と変動の監視（1日4回） |

5. `aihotel-backend` の URL（例: `https://aihotel-backend.onrender.com`）を控える。`<URL>/readyz` を開いて `"status":"ok"` が出れば起動している

## 2. デモデータと運営アカウントを作る

`aihotel-backend` の **Shell** タブで、次の2つを順に実行する。

```sh
sh /app/backend/entrypoint.sh job seed-demo
sh /app/backend/entrypoint.sh job create-platform-admin
```

- `seed-demo`: デモテナント（デモホテル東京とデモデータ）と、管理者・マネージャー・オペレーターの3アカウントを作る。**パスワードはこのとき1回だけ表示される**ので控える
- `create-platform-admin`: `BOOTSTRAP_ADMIN_EMAIL` の運営アカウントを作り、パスワードを1回だけ表示する。初回ログインで新しいパスワードの設定を求められる。
  パスワードを忘れたら、同じコマンドをもう一度実行すると発行し直せる
- 開発用の `platform@example.com / Admin1234` は作らない（公開 URL で使うと誰でも運営として入れてしまうため）

## 3. 画面（Vercel）をバックエンドにつなぐ

Vercel のプロジェクト `a-ihotel-frontend` の **Settings → Environment Variables** で:

1. `BACKEND_URL` に手順1で控えた URL を入れる（Production）
2. `NEXT_PUBLIC_DEMO_MODE` を削除する（残すとバックエンドにつながらないときにサンプル表示に切り替わる）
3. **Deployments** から最新のデプロイを **Redeploy** する

## 4. 動作確認

1. https://a-ihotel-frontend.vercel.app に運営アカウントでログインし、パスワードを変更する
2. 設定タブの下に「テナント管理（運営）」「トライアル管理（運営）」が出る。トライアルを1件発行し、その ID でログインできることを確かめる
3. 管理者アカウントでログインし、設定タブ「IP アドレス制限」の「あなたの今のアクセス元」に自分の回線の IP が出ることを確かめる
   （Vercel や Render の IP が出る場合は `TRUST_PROXY` の段数が合っていない。`render.yaml` の値を見直す）

## 補足

- `main` にマージすると、Render のバックエンドと Vercel の画面がそれぞれ自動で更新される
- README の「デモサイト」のアカウント表（`Admin1234`）はデモモードのときのもの。検証環境では手順2で表示されたパスワードを使う
- DB のバックアップ・保持期間は Render のプランに従う。本番のデータ（実際のホテルの実績）はこの環境に入れない
