# 05. 確認事項リスト

優先度: ★=これが決まらないと設計が進まない / ◎=フェーズ1着手までに必要 / 〇=フェーズ2までに必要

## A. ホテル側データ（PMS）について【最優先】

| # | 確認事項 | 優先度 | なぜ必要か |
| --- | --- | --- | --- |
| A1 | 予約明細データのエクスポート可否・形式（CSV/API/サイトコントローラー経由）・項目一覧・サンプル入手 | ★ | 全機能の土台。「フォーマットやテストデータをいただく」の具体化 |
| A2 | 予約明細に**予約受付日時**が含まれるか | ★ | 無いとブッキングカーブが構造的に作れない |
| A3 | **キャンセル済み予約**が出力に含まれるか（キャンセル日時付きで） | ★ | ネットOTB・キャンセル率予測に必須 |
| A4 | **団体/個人の判別フラグ**（または団体ブロックデータ）の有無 | ★ | セグメント分析要件（3-3）。要件メモに「予約データにフラグが必要」とある通り |
| A5 | 過去データの遡及可能期間（目標: 3年以上） | ★ | モデル学習・前年比較の可否を決める |
| A6 | チャネル（OTA/公式/電話等）のコード体系と一覧 | ◎ | チャネル別分析・チャネルマスタ設計 |
| A7 | 過去の**自社設定価格の履歴**（宿泊日×設定日ごとの料金ランク）が残っているか。PMS/サイトコントローラーのどちらにあるか | ◎ | 価格弾力性の学習に必須。無ければ運用開始後に蓄積する前提に切替 |
| A8 | 料金体系の確認: 65段階ランク表の現行版、人数別料金（1〜4名+）の実際の設定方法、税サ・食事付プランの室料分離 | ◎ | ADR定義とランク推奨の出力仕様 |
| A9 | 予算データ（月次/日別、稼働・ADR・売上）の有無と形式。日割りルール | ◎ | ダッシュボードの予算比・年度累計表示（フロントの中核機能） |
| A10 | 販売可能室数の変動（改装・アウトオブオーダー）の管理方法 | 〇 | 稼働率の分母の正確性 |
| A11 | データ更新頻度・受領方法（日次バッチの時刻、手動アップロードか自動連携か） | ◎ | パイプライン設計・「朝までに反映」のSLA |
| A12 | 個人情報（氏名・連絡先）を除外した形で出力できるか | ◎ | 受領しない設計が最も安全 |

## B. 業務運用について

| # | 確認事項 | 優先度 | なぜ必要か |
| --- | --- | --- | --- |
| B1 | 推奨価格の反映方法: 誰が・どの画面で承認し、PMS/サイトコントローラーへは手動転記か自動連携か。連携するならどの製品（手間いらず/TLリンカーン/ねっぱん等）か | ★ | 「推奨を出して終わり」か「反映まで」かでスコープが大きく変わる |
| B2 | 価格更新の頻度・タイミングの業務ルール（日次1回？随時？何日先まで見る？） | ◎ | ジョブ設計・設定タブの`autoPriceUpdate`仕様 |
| B3 | 価格のガードレール: 最低/最高価格、変更幅制限、固定したい期間（団体・契約レート等） | ◎ | 最適化の制約条件・設定画面要件 |
| B4 | 対象ホテル数（1軒から？将来何軒？）と権限体系（既存のADMIN/MANAGER/STAFF/READONLYで足りるか） | ◎ | マルチテナント設計の深さ |
| B5 | 「⑥の機能」の内容確認と、セグメント分析での個人・団体の表現方法（麻田様と協議、と記載の件） | ◎ | 未確定事項として明記されているもの |
| B6 | 月次レポートの宛先・様式（既存の社内報告様式があるならそれに合わせる）・配信方法（PDF/Excel/メール） | 〇 | レポート機能の要件確定 |
| B7 | アラート条件の業務定義（何を「赤=即時修正」とするか） | 〇 | ダッシュボードのアラート仕様 |
| B8 | KPI定義の確認: DOR・客単価の計算式、ADRの税サ扱い、稼働率の分母 | ◎ | 数字の定義がホテルと合わないと信頼を失う |

## C. 競合・外部データについて

| # | 確認事項 | 優先度 | なぜ必要か |
| --- | --- | --- | --- |
| C1 | ベンチマークホテルの具体的リスト（3〜5軒、カテゴリ・比較したい部屋タイプ） | ◎ | 競合比較機能・市場補正項 |
| C2 | 競合価格の取得手段の意思決定: レートショッパー契約（OTA Insight等・有料）/ スクレイピング（規約・法務確認要）/ 手動入力 | ★ | コスト・データ品質・法務リスクのトレードオフ。フロントは「OTA公開価格の平均（5-8ホテル）」表記を前提にしている |
| C3 | 重視するイベントの種類と情報源（会場・自治体カレンダー等）。手動登録運用の許容度 | 〇 | イベント補正の実装方式 |
| C4 | インバウンド比率・主要国籍（為替・海外祝日の効き方が変わる） | 〇 | 外部要因の優先順位付け |
| C5 | SNS・航空券価格・世界情勢データはフェーズ3以降の検討でよいか（初期スコープから外す提案） | 〇 | スコープ管理 |
