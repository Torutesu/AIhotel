# 01. 現状分析とギャップ

## 1. リポジトリの現状

### フロントエンド（Next.js 15 / React 19 / Recharts / shadcn-ui）
- 7タブ構成: ダッシュボード / ダイナミックプライシング / 日別分析 / 各種分析 / レポート / 設定 / AIまとめ + フローティングAIチャット
- **全タブがコンポーネント内のモックデータで動作しており、バックエンドへのfetch/axios呼び出しはゼロ**。フロントとバックエンドは現状未接続
- 機能MECE整理（可視化/価格最適化/BI分析）とタブ構成はよく対応しており、構造として「大枠OK」の判断と整合

### バックエンド（Express + TypeScript）
- `auth`（JWT・リフレッシュトークン・実装済） / `hotels` / `pricing` / `analysis` の4ルートのみ。pricing/analysisのサービスはモック返却のTODO状態
- Prismaスキーマ（PostgreSQL）は定義済みだが**アプリコードから未使用**（seedのみ）。User/Hotel/RoomType/PriceRank(65段階)/DailyData/DailyRoomData/Campaign/Competitor/CompetitorPriceData/Event/AuditLog

### 共有型（shared/types）
- ドメイン型・APIエンベロープ（`ApiResponse<T>`）が定義済み。ただし**フロントのモックデータの形と共有型は一致していない**箇所が多い（下記ギャップ表）

## 3. API設計の方針（フロントを正とする場合）

- **二層構成**を推奨:
  1. **画面集約API**（`/dashboard/kpi`、`/pricing/calendar`、`/daily/booking-curve` 等）— タブが1〜2回の呼び出しで描画できる形。基本分析（バッチ事前集計）と対応
  2. **汎用分析API**（`/analysis/cross?axis1&axis2&metric&from&to`）— フリー分析・任意分析（都度計算）と対応
- 共通エンベロープは既存の `ApiResponse<T>` を踏襲。日付はISO文字列に統一（現状 `Date | string` 混在）
- 予測値は実績と別フィールドで並走させ、`asOf`（いつ時点の予測か）を必ず持たせる — これがないと「過去のその時点で何と予測していたか」の検証（04）ができない
- 詳細なエンドポイント候補一覧はフロント分析より抽出済み。API仕様書（OpenAPI）化はフェーズ1の最初のタスクとする

## 4. フロント側に発生する(小さい)手戻り

構造は変えない前提で、以下は接続時に必要:
- APIクライアント層（fetchラッパ・認証ヘッダ・エラーハンドリング）とログインUI
- モックデータ生成ロジックの除去とローディング/エラー状態の追加
- ダッシュボードの「本日」が2025-10-19固定になっている等、デモ用ハードコードの除去（客室数1,280固定、人数倍率など）
