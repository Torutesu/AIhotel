## 共通仕様

- **3層データ表示原則**: 実績（確定）/ 予約=OTB（確定予約）/ AI予測（将来）を視覚的に区別する（実線/点線、ラベル、色）。予測値には基準時点（asOf）を持たせ、ツールチップ等で「いつ時点の予測か」を確認できる
- **状態設計（全画面共通）**: ローディング（スケルトン）/ エラー（再試行ボタン付き）/ データなし（初期導入時・データ未取得時のガイダンス表示）/ **データ鮮度警告**（バッチ失敗等で前日データが未反映の場合のバナー: NFR-03）
- **API契約**: `ApiResponse<T>` エンベロープ、日付はISO 8601文字列。画面集約API（1画面1〜2コール）を基本とする
- **数値定義**: ADR・稼働率等のKPI計算定義は全画面で単一のバックエンド実装を参照（フロントで再計算しない）

## SC-00 ログイン（新規）

- 目的: 認証とホテルスコープの確立
- 要素: メール/パスワード、エラー表示、（将来）パスワードリセット
- API: `POST /api/v1/auth/login`（実装済）、トークンはリフレッシュ方式（実装済）に対応するクライアント層を新設
- 要詰め: セッション有効期間、2要素認証の要否

## SC-01 ダッシュボード

- 目的: 当月の収益状況の全体把握（機能要件1-1）
- エリア構成:
  1. **アラート**: 赤（即時対応）/黄（経過観察）、対象日クリックで該当タブへ遷移
  2. **AI解説**: 当月状況の自然言語サマリ（LLM生成、日次バッチでキャッシュ）
  3. **稼働・ADR月間推移グラフ**: 日別。本日線で実績/予測を分割。左軸=稼働室数、右軸=ADR
  4. **比較パネル**: 月初比較・日付比較（前日/1週間前/先月同日/カスタム）
  5. **伸び率上位サイト**: チャネル別伸び率TOP3（表示ON/OFF設定可）
  6. **KPI進捗テーブル**: 月別×8指標×（オンハンド/AI予測/予算比[当日・累計]/前年比[当日・累計]/AI予算比/AI前年比/年度累計）
- 主要データ項目: KPI8指標 = 室料売上・販売室数・ADR・稼働率・RevPAR・宿泊人数・DOR・客単価
- API（案）:
  - `GET /dashboard/kpi?hotelId&startMonth&months`
  - `GET /dashboard/trend?hotelId&month` → `{date, occupancyActual, adrActual, occupancyForecast, adrForecast, isToday}[]`
  - `GET /dashboard/alerts?hotelId`
  - `GET /dashboard/ai-comment?hotelId&month`（キャッシュ済コメント）
- 要詰め: アラート閾値の業務定義（B7）、比較パネルの比較対象仕様、「本日」の扱い（ホテルのタイムゾーン）

## SC-02 ダイナミックプライシング

- 目的: 推奨価格の確認・承認・調整（機能要件2-1）
- エリア構成:
  1. **AI価格最適化提案**: 注目日と推奨アクションの要約（LLM生成）
  2. **着地予測サマリー**: 現在ADR/着地予測ADR/現在RevPAR/着地予測RevPAR
  3. **価格戦略設定**: 稼働率/ADR重み（合計100%）、競合追従%
  4. **日別価格カレンダー**: テーブル表示（日別行: 現在ADR・推奨ADR・推奨ランク・需要ランクA-E・稼働予測・RevPAR現/推奨）⇔ カレンダーグリッド表示（人数別価格・祝日・イベント・外部要因）のトグル
  5. **価格推移グラフ**: 現在/推奨ADR・稼働率・RevPAR
  6. **日付詳細ダイアログ**: 部屋タイプ別料金＋料金ランク、イベント/外部要因の編集（永続化）
  7. **AI分析ダイアログ**（行クリック）: 週間価格推移、**要因分解された根拠**（内部/外部要因×寄与度）、推奨アクション
- 承認UI（機能追加が必要）: 日別・期間一括の「採用/修正して採用/不採用（理由選択）」操作。FR-P07
- API（案）:
  - `GET /pricing/calendar?hotelId&month&roomType` → 日別推奨一式（推奨はランクで返しADRは導出）
  - `GET /pricing/ranks?hotelId` → 65段階ランク表＋人数別料金
  - `GET /pricing/{date}/explanation` → 根拠JSON（12で定義するフォーマット）
  - `POST /pricing/decisions` → 承認/修正/不採用の記録
  - `PUT /pricing/strategy-weights`、`PUT /pricing/{date}/event-info`
- 要詰め: 重み設定が最適化にどう反映されるか（12参照）、承認の一括操作範囲、修正時の入力単位（ランクかADRか）

## SC-03 日別分析

- 目的: 各日の詳細把握（機能要件1-2）
- エリア構成:
  1. AI日別インサイト
  2. サマリーカード（月間平均ADR/稼働率、最高/最低ADR日）
  3. **日別パフォーマンステーブル**: 過去日=実績/AI予測併記、未来日=OTB+AI予測。列: 販売室数・稼働・ADR・RevPAR・売上・YoY
  4. **ブッキングカーブ**（行クリックで対象日のカーブ表示）: リードタイム軸（日次を正とし、月・バケット集約を切替）× 累積OTB・ADR・平均販売価格。TOTAL/人数別/部屋タイプ別/チャネル別の切替（FR-V05の◎〇△に応じた表示優先）。**前年同日カーブ・基準カーブとの重ね描き**（ペース判断の根拠となるため必須とする）
  5. 曜日別パフォーマンス
  6. **競合価格比較**: 人数(1〜4名+)×競合ホテル×日別の複数系列グラフ、価格差バー、曜日別比較テーブル。出典・サンプル数・取得日時・信頼度をメタ表示
- API（案）:
  - `GET /daily?hotelId&month`
  - `GET /daily/booking-curve?hotelId&stayDate&groupBy=total|guests|roomType|channel&granularity=day|month&compare=lastYear,baseline`
  - `GET /competitors/comparison?hotelId&from&to&occupancies[]&competitorIds[]`
- 要詰め: 基準カーブの定義（過去N年同曜日平均等）、カーブの起点（365日前?）、キャンセルの表示（グロス/ネット切替）

## SC-04 各種分析

- 目的: BI分析（機能要件3-1〜3-3）
- サブタブ: チャネル / 部屋タイプ / 予約期間（リードタイムバケット） / 顧客セグメント（ビジネス・レジャー・家族・団体・VIP等） / 人数別 / 競合価格 / 年間推移 / **フリー分析**
- フリー分析: 軸1×軸2（チャネル/部屋タイプ/リードタイム/セグメント/曜日/日付）× 集計指標（室数/稼働/ADR/RevPAR/売上/予約件数）の都度クロス集計（FR-A02）
- セグメント別クロス分析設定: 期間・軸5種（チャネル/地域/個人団体/キャンセル/その他）・表示項目・個人/団体/TOTAL・部屋タイプ加算・バッチ登録（FR-A03）
- キャンペーン管理: 参画キャンペーンCRUD、OTA取込（FR-A04）
- API（案）: `GET /analysis?dimension=...`（バッチ集計参照）、`GET /analysis/cross?axis1&axis2&metric&from&to`（都度計算）、`GET/POST /analysis/cross-settings`、`GET/POST/PUT/DELETE /campaigns`
- 要詰め: 顧客セグメントの分類ロジック（PMSデータから機械的に判定できるか）、地域軸の粒度、「⑥の機能」（B5）

## SC-05 レポート

- 目的: 月次総括ほか定型レポート（機能要件1-3）
- 要素: レポート生成（月次/四半期/年次/カスタム期間、PDF/Excel/CSV）、クイックレポート、生成履歴、定期配信設定（頻度・宛先・形式）、テンプレート
- API（案）: `POST /reports/generate`（非同期ジョブ+完了通知）、`GET /reports`、`GET/POST /reports/schedules`
- 要詰め: 月次レポートの様式（既存社内様式に合わせるか: B6）、AIコメントをレポートに含めるか、配信手段（メール）

## SC-06 設定

- 要素: ホテル情報（総客室数等 — KPI分母に直結するためマスタ扱い）/ 表示設定 / 通知設定（アラート閾値・日次/週次レポート）/ システム設定（**自動価格更新トグル・更新間隔**・データ保持日数）/ ダッシュボード表示設定
- 追加が必要な設定（要件から逆算）: 競合ホテルの登録・管理、料金ランク表の閲覧/編集、ガードレール設定（FR-P06）、チャネルマスタ管理、予算の登録/取込
- API（案）: `GET/PUT /settings`、`GET/POST/PUT /competitors`、`GET/PUT /price-ranks`、`POST /budgets/import`
- 要詰め: 設定変更の権限（ロール×設定項目のマトリクス）、料金ランク表を誰が編集できるか

## SC-07 AIまとめ

- 目的: 外部要因ベースの先6ヶ月市場動向予測（マクロビュー）
- 要素: AI総合コメント / 月別需要指数グラフ（100=平均、気候・インバウンド・イベント・アクセスの要因内訳） / 週別要因積み上げ / 外部要因カテゴリカード（各要因のステータス・トレンド・KPI・出典） / 注意事項（免責）
- API（案）: `GET /ai-summary/forecast?hotelId&months=6`
- データ源: 外部要因テーブル（12のデータ取得基盤が供給）。要因KPI（例: 台風の想定キャンセル室夜、為替感応度）は予測サービスが算出し、LLMはコメント化のみ
- 要詰め: 需要指数の定義（何を100とするか）、表示する要因カテゴリの確定、更新頻度（週次?）

## SC-90 AIチャット

- 目的: 画面を横断した自然言語での質疑（「来週の金曜、強気にして大丈夫?」等）
- 入力コンテキスト: 現在表示中の画面・対象期間・当該ホテルのKPI/OTB/推奨・根拠JSON（**LLMに渡す範囲を定義**: NFR-06）
- API（案): `POST /chat`（SSEストリーミング）。会話履歴の保存有無は要詰め
- ガード: 数値・固有名詞は注入コンテキスト由来のみ（FR-L03）。範囲外の質問（一般質問等）の応答方針を定義
- 要詰め: 履歴保存・監査対象とするか、チャットから操作（価格変更等）を許すか（初期は閲覧のみを推奨）
