# AIレベニュー管理システム 販売代理店向け説明（テキスト版）

対象: 販売代理店・導入担当。ホテルに説明するときの「型」と、ティア（おまかせ／標準／詳細）の選び方をまとめたもの。
スライドではなくこのままメモとして使う前提。図は文字図（コピーしてそのまま貼れる）。

---

## 1. 一言でいうと

「ホテルの毎日の客室価格を、AIが理由付きで提案し、ホテルの方針に合わせて自動または半自動で運用するサービス」

売り物は「価格の精度」だけではなく、次の3つのセット。

1. 予測と価格提案（アルゴリズム）
2. ホテルごとの方針を反映する仕組み（個社MD）
3. 毎朝5分で回る運用と、対話での修正（ダイジェスト・チャット）

---

## 2. 3層の制御（これが説明の芯）

```
┌───────────────────────────────────────────────────────────┐
│  個社MD（ホテルごと）   ヒアリングで決めた方針・制約      │  ← 一番強い
│   例: 最低価格 9,500円 / 競合Cは見ない / 天候は効かない   │
├───────────────────────────────────────────────────────────┤
│  汎用MD（全ホテル共通） レベニューマネジメントの基礎      │  ← 判断の根拠
│   例: 連休前夜は強い / 満室が見えたら単価を優先          │
├───────────────────────────────────────────────────────────┤
│  アルゴリズム（共通）   予測・価格計算・実績からの学習    │  ← 土台
│   例: 予約ペース / 祝日 / イベント / 天候 / 競合価格      │
└───────────────────────────────────────────────────────────┘
        優先順位:  個社の制約 ＞ 学習した係数 ＞ 汎用の既定
```

ホテルへの言い方:
「土台の計算は全ホテル共通です。御社の事情（最低価格、見ない競合、団体の扱い）はヒアリングして文書にし、それが計算より優先されます。基礎の考え方は共通資料から引用して説明します。」

---

## 3. ティア（説明の深さと任せ方）

アルゴリズムは全ティア同じ。変わるのは「どこまで説明するか」「どこまで任せてもらうか」。
ティアは **ホテルの規模ではなく、レベニューマネジメントの体制と理解度** で決める（大手でも専任がいなければ標準、旅館でも専任がいれば詳細で良い）。

### マトリックス

| | おまかせ | スタンダード（標準） | エンタープライズ（詳細） |
|---|---|---|---|
| 想定ホテル | 旅館・小規模・専任なし | 中規模・支配人やフロント責任者が兼任 | 大手・チェーン・レベニューマネージャー専任 |
| 価格の決め方 | **システムが自動で適用**（例外だけ確認） | AIが提案、担当者が毎朝「採用／据え置き」 | AIが提案、担当者が理由を見て判断・上書き |
| 説明の深さ | 結論と一言の理由だけ（専門用語なし） | 主な要因2〜3個と根拠（用語は言い換え） | 要因のpt内訳・候補・信頼区間・要因評価まで |
| 自動採用の既定 | オン | オフ | オフ |
| 画面で前に出すもの | 今日の価格と変更点 | 今日決めるべき日・理由 | 全部（評価・モデル比較・係数） |
| ヒアリング量 | 30分（最低価格・団体・休館・見ない競合） | 1時間（＋需要レベル別の方針・競合の扱い） | 2時間（＋要因の効き方・禁止事項・運用ルール） |
| 導入後のこちらの関与 | 月1で結果報告、例外対応 | 月1で採用率と精度の確認 | 四半期でモデル評価・係数レビュー |
| こちらの工数 | 小（運用はシステム） | 中 | 大（説明と調整） |

### どのティアを取るか（決め方）

```
専任のレベニュー担当がいる？
   ├─ はい → 数字で判断したい？ ─ はい → エンタープライズ
   │                              └ いいえ → スタンダード
   └─ いいえ → 毎朝5分、価格を見て判断できる人がいる？
                  ├─ はい → スタンダード
                  └─ いいえ → おまかせ
```

迷ったら **スタンダードで始めて、運用の様子で上下** させる。ティアは個社MDの「ティア:」1行（または設定画面）で切り替わり、翌日から説明の深さと自動採用の既定が変わる。

### 説明の言い分け（同じ状況をどう言うか）

状況: 9/20（土）は3連休の中日で、AIは R25 → R29 を推奨。

- おまかせ: 「9/20（土）は連休の中日なので 23,400円 に上げておきます。団体や休館の予定があれば教えてください。」
- スタンダード: 「9/20（土）は3連休の中日で予約の入りも早いので、R25→R29（23,400円）を推奨します。据え置くなら理由を残してください。」
- エンタープライズ: 「9/20（土）: 予測稼働 82%（p10〜p90: 71〜90%）。要因は連休中日 +12pt、ペース +4pt。候補は稼働率重視 R27 / ADR重視 R31 / 競合追従 R28、重み 40/40/20 で R29。期待RevPAR 19,838 → 20,802円。」

## 4. 導入の流れ（代理店が案内する手順）

```
① ヒアリング ──→ ② 個社MD作成 ──→ ③ 反映・再計算 ──→ ④ 精度確認 ──→ ⑤ 運用開始
   30分〜2時間      テンプレに記入      保存すると自動       バックテスト        毎朝5分
   （ティアで量が変わる）  「## ルール」節      ガードレール等       要因の評価          ダイジェスト＋チャット
```

1. **ヒアリング**: `docs/knowledge/templates/個社MDテンプレート.md` の順に聞く。ティア、最低価格、見ない競合、団体、効かない要因、禁止事項が最低限。
2. **個社MD作成**: テンプレに書き込み、設定タブ「個社MD」に貼って保存。解釈できない行はその場でエラー表示されるので直す。
3. **反映**: 保存時にランク範囲・最低価格・変動幅・除外競合・固定係数・自動採用が反映され、需要予測が再計算される。
4. **精度確認**: 過去実績を取り込み、バックテストと「要因の評価」で効き方を見る。効かない要因は個社MDで固定する。
5. **運用開始**: 日次ジョブを有効化。毎朝のダイジェストとチャットで回す。

---

## 5. 毎日の運用（ホテル側の体験）

```
 04:00  天候・祝日・イベント・競合を取り込み → 365日分を予測 → 価格提案 → 前日の実績で学習
 09:00  担当者が「今日決めるべき日」を見る（期待増収額順）
          おまかせ:   自動で適用済み。例外だけ通知
          標準/詳細:  採用 or 据え置き（理由を残す）
 随時    チャットで「なぜこの価格？」「工事があるから下げて」→ 説明 or 設定変更（記録に残る）
 翌朝    答え合わせ（予測と実績の差）→ 係数を自動修正
```

## 6. よくある質問への答え方

- **「精度はどれくらい？」**: 予約データ（OTB）が入ってからが本番。目安は7日前で稼働率±5〜8%、30日前で±10〜15%。導入初期は方針（個社MD）で守り、データが溜まるほど学習で寄せる。
- **「なぜこの価格か分からないのでは？」**: すべての提案に理由の内訳が付き、チャットで「なぜ」に答える。根拠は基礎資料と御社の方針から引用する。
- **「勝手に値段を変えられたくない」**: 自動採用はおまかせ以外オフ。最低価格・変動幅・ランク範囲の制約が先に効く。変更はすべて記録に残る。
- **「うちは天気で客が動かない」**: 個社MDで「効かない要因: 天候」と書けば係数が0に固定され、学習でも動かない。
- **「団体で満室のときは？」**: 個社MDの「団体」方針に従い、10室以上は自動採用しない等の運用にできる。
- **「競合の売止めに引っ張られない？」**: 団体の売止めはチャットで「実需ではない」と伝えれば除外され、再計算される。

## 7. 説明時に使う図（コピー用）

### 予測から価格まで

```
 過去実績・予約ペース ─┐
 祝日・連休 ──────────┤
 イベント（承認済み） ─┼→ 需要予測（稼働率＋理由の内訳）→ 価格決定（重み: 稼働率/ADR/競合）→ ガードレール → 推奨ランク
 天候（直前のみ） ─────┤                                           ↑
 競合価格・売止め ─────┘                                    個社MDの制約が先に効く
```

### 学習の輪

```
 提案 → 採否（理由付き） → 実績 → 答え合わせ → 係数を修正 → 翌日の提案
   ↑                                                  │
   └──────────── 個社MDで固定した係数は動かない ────────┘
```
