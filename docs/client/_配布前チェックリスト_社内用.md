## 必ず編集する箇所

### `ご確認事項一覧.md`

- [ ] 冒頭表の「ご回答期限」「弊社担当」を記入する
- [ ] **A-1 の「サンプルとして拝見した形式では、この項目が含まれておりませんでした。」**
      — データを拝見していない施設さまでは**削除**する（他社データに言及していると
      受け取られかねない）
- [ ] **A-6 の「サンプルデータを拝見したところ」** — 同上。データ未受領の施設さまでは
      セクションごと削除するか「一般的に多く見られる」表現に置き換える
- [ ] E章「弊社で検討している事項」— 社外に出してよい内容か毎回判断する。
      迷う場合は章ごと削除してよい

### `レベニュー運用仕様_ご説明.md`

- [ ] §7「現時点でできること／これからのこと」を最新の実装状況に更新する。
      **未実装のものを実装済みとして渡さない**（特にPMS連携・OTA自動収集・
      需要予測ML・AIコメント生成）
- [ ] §2.2 の展開例の数値は説明用のダミー。実データを載せる場合は
      **その施設さま自身のデータのみ**にする

## 他社情報の混入チェック

配布前に必ず実行する。

```bash
grep -nE 'NEHOPS|新宿ワシントン|藤田|他社名' docs/client/*.md
grep -nE 'Prisma|DailyData|PriceRank|F-DASH|F-DP|F-SET|AGENTS|AG-[0-9]|レビューシート' docs/client/*.md
```

どちらも**検出ゼロ**であること。

## 表現の原則

- 社内の管理ID（F-xx / AG-xx / レビューシートのID）を出さない。
  出してよいのはヒアリングシートの設問番号（P-01 / D-01 など）のみ
- DBのテーブル名・カラム名・技術スタックを出さない
- 他の施設さまの実データ・コード体系・回答内容を出さない
- 「実装が止まる」「ブロッカー」等の社内都合の表現を使わない。
  お客さま視点では「先にご確認いただきたい」
- 未実装の機能を実装済みとして書かない。開発中のものは開発中と明記する
- 推定値を実績のように見せない（システムの表示方針と同じ）
