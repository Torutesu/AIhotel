# 現地データ取得テスト 手順・記録（2026-09-15 / NEHOPS × TL-リンカーン）

対象Issue: #6（連携方式）、#18（A1〜A12 提供仕様）、#24 E2（OTBスナップショット）、#9（競合価格は別ルート）

## 0. 前提と役割分担

現地で使える端末は **ホテルの業務用PC（Windows）1台のみ**。フロント業務と共用のため、
**この端末には何もインストールせず、参照とエクスポートだけを行う**。

| 場所 | やること | 使うもの |
|------|---------|---------|
| ホテル業務用PC | TL-リンカーン／NEHOPS にログイン、CSVエクスポート、列の確認、個人情報列の除去 | Windows標準のPowerShell（`tools/field-test/Inspect-ReservationCsv.ps1`）。動かなければExcelで代替 |
| 持参PC（社内） | CSVをプロダクトのDBへ取り込んで動作確認 | `pnpm --filter backend import:reservations` |

- 業務用PCから外部へのファイル送信はしない（ネットワークポリシーが未確認）。持ち出しはUSB等の合意済み手段で。
- **在庫・料金・プランの更新系操作は行わない。** TL-リンカーンは実際に販売中の在庫と料金を握っており、
  テスト操作がそのままOTAへ反映されうる。
- 個人情報は受領しない設計が最も安全（A12）。氏名・連絡先の列は現地で落としてから持ち出す。

## 1. ホテル業務用PCでの手順

1. TL-リンカーンにログインし、**予約検索画面から直近1か月をCSV出力**する（A1）。
2. 出力したCSVをそのまま開いて列名を確認する。次の列があるかを見る:
   宿泊日/チェックイン日・泊数・室数・人数・室料・**予約受付日（A2）**・**取消日またはステータス（A3）**・
   **団体区分（A4）**・販売先（A6）・室タイプ。
3. 列の一覧・空率・日付列の期間をまとめるなら、USB等に置いたスクリプトを実行する（インストール不要・通信なし）:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Inspect-ReservationCsv.ps1 -Path .\予約明細.csv
   ```

   実行できない場合（実行ポリシーが組織設定で禁止等）は、Excelで開いて列名を書き写す。スクリプトは必須ではない。
4. 個人情報列を落としたコピーを作り、**持ち帰るのはそのファイルだけ**にする（A12）:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Inspect-ReservationCsv.ps1 -Path .\予約明細.csv -DropColumns 宿泊者名,電話番号
   ```

   TL-リンカーン側の出力項目設定で氏名・連絡先を外せるなら、そちらを使うほうが確実。
5. キャンセルを含む条件で再出力し、キャンセル行が残るか・取消日が付くかを確認（A3）。
6. 出力期間の最古を指定して遡及限界を確認（A5）。統計データ（販売先別・室タイプ別・ブッキングカーブ等）も1つ試し出力してCSVの形を見る。
7. 自動出力・スケジュール機能の有無を確認（A11）。
8. NEHOPS 側で実績・部屋タイプ別・予算の出力範囲と締め時刻を確認（A9・A10・A11）。
9. NEHOPS ↔ TL-リンカーン の連携形態（どちらが在庫・料金の正か、2WAYか片方向か）を現場に確認。
   ※ シーナッツ公開ページの2WAY対応PMS一覧にNEHOPSの記載が見当たらないため、実態を確認する。
10. 端末を常設する前提の確認: 置き場所・電源・ネットワーク（外部送信の可否、プロキシ、固定IP）、
    業務用PCと兼用でよいか（常駐させるなら単一障害点になる点も共有する）。

## 2. 持参PCでの取り込み手順

```bash
# 事前（社内で済ませておく）
docker compose -f docker/docker-compose.dev.yml up -d
pnpm --filter backend db:generate
pnpm --filter backend db:migrate && pnpm --filter backend db:seed

# ① 列を調べる（DB不要・マッピング不要）
pnpm --filter backend import:reservations -- --file ./予約明細.csv --inspect

# ② 列マッピングを書く（src/scripts/mapping.example.json をコピーして列名を実物に合わせる）

# ③ 変換結果を確認する（DBは読むだけ・書き込まない）
pnpm --filter backend import:reservations -- \
  --file ./予約明細.csv --mapping ./mapping.json --hotel-id demo-hotel-001

# ④ 取り込む（--write を付けたときだけ書き込む）
pnpm --filter backend import:reservations -- \
  --file ./予約明細.csv --mapping ./mapping.json --hotel-id demo-hotel-001 --write
```

補足:

- 文字コードは既定 Shift_JIS(CP932)。UTF-8なら `--encoding utf8`、タブ区切りなら `--delimiter tab`。
- 取り込み先は `DailyData` / `DailyRoomData` / `OtaChannelData` / `BookingCurveData`。
  すべて upsert なので同じCSVを何度流しても行は増えない。
- `bookedAt`（予約受付日）をマッピングすると、ブッキングカーブを遡って再構成する（#24 E2）。
  列が無い場合はカーブが作られない旨を警告して続行する。
- 室タイプは `RoomType.code` と突き合わせる。一致しないコードは取り込まずに一覧で報告する。
- `--as-of` にはCSVを出力した日を渡す（既定は実行日）。それより未来のカーブ点は作らない。
