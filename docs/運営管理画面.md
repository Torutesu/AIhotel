# 運営管理画面

`/operations` に運営専用UIを配置。顧客向け設定にはテナント・トライアル管理を表示しない。

- 専用環境の `NEXT_PUBLIC_DEMO_ADMIN_CONSOLE=true` のときのみルートを提供。それ以外は404。
- ログイン後の `PLATFORM_ADMIN` だけがコンソールを使用できる。他ロールではデータ取得も開始しない。
- 実APIの `/platform/*` は既存の authenticate / requireRole('PLATFORM_ADMIN') を維持。
- デモのトライアルAPIは専用環境フラグと、サーバー検証する運営セッションCookieの両方が必要。
- 運営ログイン後はホテル画面から `/operations` へ移動。

概要・顧客一覧・利用状況・トライアル管理をURLのsectionで切替。顧客・トライアル検索、未ログイン・期限間近の絞り込み、テーマ変更に対応。
スマホのトライアル一覧はカード状に表示。

## デモのデータ境界

デモ環境の顧客・ホテル情報はサンプル。トライアルの発行・延長・停止等は共有保存に反映する実操作。
概要ではトライアルの最終ログイン・期限を表示し、活用状況では計測開始後の機能別操作を集計する。滞在時間は未計測。

## 検証

- フロント359テスト、バックエンド372テスト成功（DB統合263件はDATABASE_URL未設定でスキップ）。
- 型チェック・lint・ビルド成功。
- 公開プレビューをChrome 1440px / WebKit 375px、明暗それぞれ4画面で検証。ページの横はみ出し・pageerrorなし。
- 検索、発行ダイアログ、未認証トライアルAPIの401を確認。
- 運営以外の3ロールでは運営データを取得しないテスト、専用環境以外で404になるテストを追加。
- 実機Safari・DB接続E2Eは未検証。

## 活用状況（2026-11-25）

運営の「活用状況」で7/30/90日、顧客名検索、顧客別の日別・機能別内訳を表示。
画面遷移と料金ランク保存・レポート出力・チャット回答成功を区別。滞在時間・売上改善効果・未実装の業務操作は計測しない。
トライアルは署名済みセッションから本人IDを確定し、日別の回数のみ共有保存。任意の顧客IDを入力して書き込めない。
質問本文・回答本文・料金の入力値は保存しない。競合する更新はCASで保護。1アカウント毎分120件まで。
読み取りは運営専用。配布側URLのGETは403、POSTは有効な本人セッションが必要。
計測開始前の履歴は復元しない。未記録を未利用と断定しない。
実API版は認証・ホテル所属確認後に本人のUSAGE監査レコードを記録し、運営だけがホテル別に集計する。
実API版のコードは準備済みだが、公開デモは共有保存版を使用する。バックエンド実運用への接続・DB統合検証は別途必要。
