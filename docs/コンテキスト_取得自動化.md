## 1. 目的

ホテル（テナント）のサイトコントローラー **TL-リンカーン** と PMS **NEHOPS** から、予約明細を
**毎日1〜2回、人手なしで取り続ける**。1回取れるかではなく、継続して取れる状態が完了条件。

取れたCSVは、このプロダクトの実績（日別・チャネル別・客室タイプ別・ブッキングカーブ）に取り込む。

## 2. 前提（取り違えると設計を間違える）

| 項目 | 内容 |
|------|------|
| API | 公式APIは使わない前提。画面操作、またはHTTPリクエストの再現で取る |
| IP制限 | TL-リンカーンにIP制限がある。**ホテルの端末・ホテルのネットワークから出た通信でないと弾かれる** |
| 実行場所 | ホテルのWindows端末1台（業務用PC・フロント業務と共用）。**構成A: エージェントもブラウザもこの端末で動かす** |
| 端末の制約 | インストーラを使わない／管理者権限を前提にしない／レジストリ・Program Filesを汚さない。USBの携帯キットから実行する |
| 使えないもの | browser-use Cloud、Codex自身のクラウド側ブラウザなど、**相手のクラウドIPから出る実行**はTLに届かない |
| 禁止操作 | **在庫・料金・プラン・予約内容の更新系は絶対に触らない**。TL-リンカーンは販売中の在庫と料金を握っており、誤操作がOTAの販売価格に反映される。参照とエクスポートのみ |
| 認証情報 | コードに書かない。DPAPIで暗号化したファイル、またはキット内の設定ファイルから読む。ログ・スクショ・コミットに残さない |
| ログイン | エージェントにログインさせない。**人が手動でログインしたChromeに、CDP（`--remote-debugging-port=9222`）で接続**して使う |
| 個人情報 | 予約一覧には宿泊者名・連絡先が出る。エージェントは画面内容をLLMに送るため、扱いはホテル側と合意が必要。CSVは氏名・連絡先の列を落としてから持ち出す |

## 3. 決まった方針

1. **日々の取得は決定論的スクリプト**で回す（`export-tl.mjs` + `selectors.json`、またはHARからのPowerShell再現）。1回あたりの課金ゼロ、数秒、失敗は終了コードで分かる
2. **壊れた日だけエージェントが肩代わり**する（`Invoke-Pipeline.ps1 -AgentFallback`）。どちらの経路で取れたかはログに残り、エージェント経由が続けばセレクタを直す合図
3. エージェントは **Codex（モデル: Astra）を主役**にする。実運用での精度が高いことを確認済み。この自動化専用のCodexアカウントを用意する。**browser-use は二段目の保険**
4. 探索（初回に手順を見つける作業）の完了条件は「CSVが1回落ちること」ではなく、**`selectors.json` を埋めて `run.cmd` がエージェント無しで通ること**
5. 自分のPCから同じChromeを操作する構成B（CDPリレー）は**最終手段**として持つ。AとBを同時に操作させない。同じLAN内からのみ

## 5. 当日の流れ（要点）

詳細は `docs/当日手順_Windows実行.md`。

1. 環境確認（端末から自社APIへHTTPSで出られるか／外部LLM APIへ出られるか／USB実行可否／実行ポリシー／タスク登録可否）
2. Chromeをデバッグポート付きで起動し、手動でTL-リンカーンにログイン
3. Codexで探索: `codex-discovery-prompt.txt` を渡し、`selectors.json` を埋めて `run.cmd --days 30 --headed` が通るまで
4. 通らなければ browser-use: `agent.cmd --days 30`
5. 列マッピングを取込APIに登録 → dry-run → 本番送信 → 画面で実データを確認
6. `Invoke-Pipeline.ps1`（`-AgentFallback`）をタスクスケジューラに1本登録し、その場で1回無人実行
7. 撤収: キットの設定ファイル（APIキー）、Chromeプロファイル（ログインセッション）、`%USERPROFILE%\.codex` を削除

## 6. 未確定・現地で確認すること

| 項目 | なぜ重要か |
|------|-----------|
| **NEHOPS がブラウザで動くか、専用クライアントか** | ブラウザならTLと同じ流れに乗る。専用クライアントの場合の取り方は未検討 |
| TL-リンカーンに出力のスケジュール機能があるか（A11） | あれば画面操作自体が不要になる |
| 端末から自社APIへHTTPSで出られるか | 出られなければ継続送信が成立しない |
| 端末から外部LLM APIへ出られるか | エージェントを動かす前提 |
| USBからの実行・タスクスケジューラ登録が許可されるか | 無人実行の前提。業務用PCの設定変更にあたるためホテル側の許可が要る |
| Codex CLIの非対話実行の書式、ブラウザ操作機能の有無（版依存） | `codex-fallback.cmd` を埋めるのに必要 |
| 予約明細CSVの列（予約受付日 A2・取消日/ステータス A3・団体区分 A4・販売先 A6） | 取込の列マッピングと、ブッキングカーブが作れるかが決まる |
| 画面内容をLLMに送ることへのホテル側の合意 | 個人情報が含まれる |
| サブスクのCodexを無人の定期実行に使う扱い（規約） | フォールバック用途でも事前確認しておく |

## 7. コスト感（参考）

- 日次は決定論なので**1回あたりゼロ**。エージェントは壊れた日だけ動く
- 探索日の費用は、browser-use（従量）なら数ドル〜$20程度。Codex専用サブスクなら定額内
- エージェントの使用量は `tools/rpa/agent/out/result_*.json` の `usage` に記録される
- 詳細は `tools/rpa/README.md` §5-4-b / §5-4-c

## 8. Codexに最初に頼みたいこと

現地の端末上で、`tools/rpa/agent/codex-discovery-prompt.txt` の内容を実行すること。完了条件は、
**`tools/rpa/selectors.json` を実在するセレクタで埋め、`run.cmd --days 30 --headed` がエージェント無しで成功すること**。
コード（`export-tl.mjs`）は変えずにJSONだけで通す。通らなければ、原因と試したことを報告する。

リポジトリに変更を加える場合は、このブランチに対して行い、`AGENTS.md` の検証コマンドを通してからコミットする。
HAR・画面HTML・trace・CSVサンプル・スクリーンショットには認証情報や個人情報が入るので、**コミットしない**。
