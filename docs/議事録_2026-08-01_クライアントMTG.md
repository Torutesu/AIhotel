## 開発

### 全体方針
- **スマホ対応は無しで良い**（決定）

### 1. PMS/サイトコントローラー連携（No.56, 57 → [#6](https://github.com/Torutesu/AIhotel/issues/6)）

対象PMS候補:
- NEHOPS（アプリ）
- TAPホテルシステム
- [OPERA](https://www.oracle.com/jp/hospitality/opera-property-services/)（IDeaS紐付き）
- アルメックス

データ取得方式:
- ホテルのネットワーク環境を使うことが前提。そこからどうデータを吸い上げるかが論点
- **Windows端末を1台用意いただき、そこからデータを吸い上げてプロダクト側に送る**（端末をレンタルして提供することも検討）

サイトコントローラー:
- TLリンカーン（リクルート）/ 手間いらず / ねっぱん

### 2. 競合価格・OTAスクレイピング（No.54 → [#9](https://github.com/Torutesu/AIhotel/issues/9)）

国内:
- 楽天トラベル / じゃらん / 一休
- **各ホテルの公式HP**（最安値保証があるため）
  - ブッキングエンジンは分散しており個別対応が発生する可能性が高い: [OPTIMA BOOKING](https://sys.ne.jp/solutions/optima) / [tripla](https://tripla.io/)

海外:
- Booking.com / Agoda / Expedia / Trip.com

### 3. 団体客の扱い（No.53 → [#10](https://github.com/Torutesu/AIhotel/issues/10)）

- 団体をカウントするかしないか選択可能に（個人客＝FITだけで見るオプション）
- 団体の種類によってキャンセル率は変わる（上から順にキャンセル率が低い）:
  1. 修学旅行・教育旅行
  2. 法人旅行・インセンティブ旅行
  3. 募集旅行
- この分類ができているホテルとできていないホテルがある → **団体種別の識別が必要**（コンサルティング対応も含む）
- 地方に行くほど団体客の取り扱いが多い
- 桜の開花時期や紅葉のタイミングでも人の動きが変わる（季節要因）
- 減る可能性のある部屋数を個人販売に回していく

### 4. アカウント体系（→ [#11](https://github.com/Torutesu/AIhotel/issues/11)）

| 区分 | 権限 |
|------|------|
| 本部管理 | グループの全ホテルアカウントに入れる |
| 管理者・オペレーター | 操作可能。承認ボタンを押す → サイトコントローラーへ流し込み |
| 閲覧のみ | 操作不可。AIチャットは利用可能 |

> ⚠️ 現行の確定値「ロール3種（ADMIN/MANAGER/OPERATOR）」の変更を伴うため、仕様確定後に `AGENTS.md`・`要件定義書.md` を更新する。
