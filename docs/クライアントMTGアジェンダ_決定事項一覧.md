## 1. PMS／サイトコントローラー連携（★★★・課題No.56, 57）（15分）

Phase 4 の中核。**仕様提供待ちで完全に着手不能**の状態。

| # | 決めること | 選択肢・確認ポイント |
|---|-----------|---------------------|
| 1-1 | 利用中のPMS製品名・ベンダー・バージョン | 連携仕様書の入手ルート（ベンダー経由か直接か） |
| 1-2 | サイトコントローラーの製品 | TLリンカーン／ねっぱん／手間いらず 等 |
| 1-3 | データ連携方式 | API（REST/SOAP）／CSVファイル連携／DB直結。API仕様書・認証情報の提供時期 |
| 1-4 | 連携頻度 | リアルタイム／日次バッチ（何時台か）／手動アップロード |
| 1-5 | 取得データの粒度 | 予約単位か日別集計か。キャンセル・変更の反映方法、利用人数・部屋タイプ・プラン情報の有無 |
| 1-6 | 検証環境 | テスト用PMSアカウント／サンドボックスの提供可否と時期 |
| 1-7 | 価格の書き戻し（自動反映） | 現在スコープ外。将来必要なら時期と対象（サイトコントローラーのみ？）を確認 |

**決まらない場合の影響**: Phase 4 の連携アダプター設計に着手できず、実データ運用が開始できない（現状はseedデータ運用のまま）。

## 2. 競合価格・OTAスクレイピング（★★★・課題No.54、F-SET-03）（10分）

DBスキーマ（`Competitor.otaUrls`）は用意済みで、**URL提供待ち**。

| # | 決めること | 選択肢・確認ポイント |
|---|-----------|---------------------|
| 2-1 | 競合ホテル5社の確定 | ホテル名の最終リスト（施設ごとに異なる場合は施設別リスト） |
| 2-2 | 対象OTA | 楽天トラベル／じゃらん／Booking.com 等、どのサイトの価格を取るか。各競合のURL提供 |
| 2-3 | 取得手段の方針 | スクレイピング（各OTAの利用規約リスクの許容判断）か、公式API契約か |
| 2-4 | 取得条件 | 頻度（日次？時間帯）、取得プラン条件（1名/2名/3名以上、素泊まり/朝食付き等の統一基準） |
| 2-5 | 口コミ評価点（F-ANA-04・課題No.45, 46） | 収集元サイト・頻度。自動収集か当面手入力運用か |

## 3. テーブル条件・データ仕様（★★★・要件定義書§8.1）（10分）

スキーマは変更吸収できる設計だが、**確定しないとseed→実データ移行と帳票が固まらない**。

| # | 決めること | 選択肢・確認ポイント |
|---|-----------|---------------------|
| 3-1 | 団体客レベニュー影響ルール（課題No.53、F-SET-05） | 「団体」の定義（室数・人数の閾値）、ブロック（仮押さえ）と確定の扱い、稼働率・ADRへの算入ルール。→ `GroupBooking` スキーマ確定 |
| 3-2 | 利用人数別実績の粒度（課題No.47, 48） | 現行「1名/2名/3名以上」の3区分で確定してよいか |
| 3-3 | 予算データ（F-SET-04） | 提供形式（Excel？）、更新頻度（年1回＋期中修正？）、誰が入力するか |
| 3-4 | 過去実績データの提供 | 移行対象期間（例: 過去2〜3年分）、形式、提供時期。AI学習・前年比表示の両方に必要 |

## 5. インフラ・セキュリティ（★★・要件定義書§8.1）（10分）

コードはクラウド非依存に作ってあるが、**本番構築はクラウド確定が前提**。

| # | 決めること | 選択肢・確認ポイント |
|---|-----------|---------------------|
| 5-1 | クラウド事業者 | AWS か GCP か（藤田観光側の社内標準・既存契約の有無） |
| 5-2 | 契約主体 | クラウド契約・費用負担はクライアントか提供側か。アカウント管理者 |
| 5-3 | DB | マネージドPostgreSQL（RDS / Cloud SQL）か Supabase か |
| 5-4 | ドメイン・URL | 現在 hotel-price.vercel.app。本番の独自ドメイン取得と管理者 |
| 5-5 | セキュリティ要件 | 藤田観光側のセキュリティチェックリスト／審査プロセスの有無、IPアドレス制限・SSOの要否 |
| 5-6 | 可用性・バックアップ | SLA 99.5%の合意、バックアップ頻度・保持期間、障害時の連絡体制 |
| 5-7 | 個人情報の扱い | 連携する予約データに宿泊者個人情報が含まれるか。含まれる場合の保持期間・マスキング方針 |
