# 現地端末で動かす取得ツール（IP制限があるため端末側で実行する — #6）

TL-リンカーンにIP制限があり、ホテルの端末・ホテルのネットワークからしかアクセスできない前提。
そのため取得処理も**その端末の上で動かす**。ここには端末で使う道具を置く。

業務用PCなので、置ける／動かせるものが限られる。**確認できた条件に応じて上から選ぶ**。

| 優先 | 方式 | 端末に必要なもの | 判断の材料 |
|------|------|----------------|-----------|
| 1 | **PowerShellでHTTPリクエストを再現** | なし（Windows標準） | 現地で取ったHARを見て、エクスポートが素直なリクエスト1本なら成立。いちばん軽く壊れにくい |
| 2 | **携帯版Playwright（USBから実行）** | USBのフォルダ一式（インストーラ不要・管理者権限不要） | USBからの実行が許可されているか。`Setup-PortablePlaywright.ps1` で事前に作る |
| 3 | **Power Automate Desktop** | Windows 11なら標準搭載 | 1・2が使えない場合。GUIでフローを組む（手作業が増える） |
| 4 | **エージェント型（browser-use / jev-ultrafast）** | Python(uv)＋Chrome＋LLM APIキー＋外部APIへの通信 | 初回の探索と壊れたときの復旧に使う。定期実行は1〜3に任せる。→ §5 |

どの方式でも、落としたCSVの送り先は既存の取込APIで共通（`tools/field-test/Send-ReservationCsv.ps1`）。

## 現地で最初に確認する4点（方式が決まる）

1. **端末から自社APIへHTTPSで出られるか** — 出られなければ、そもそも継続送信が成立しない（プロキシ設定・許可申請の対象を特定する）
   ついでに**外部LLM APIへ出られるか**も見る（エージェント型を使う場合の前提）
2. **USBから実行ファイルを起動できるか** — AppLocker等で止められていないか
3. **PowerShellの実行ポリシー** — `powershell -ExecutionPolicy Bypass -File` が通るか
4. **タスクスケジューラに登録できるか** — 無人実行の前提

## 1. PowerShellでリクエスト再現（HAR待ち）

HARを見てから書く。組み立てに必要な情報は次の5つ。

- ログインのリクエスト（URL・メソッド・パラメータ・CSRFトークンの出所）
- セッションの持ち方（Cookie名）
- エクスポートのリクエスト（URL・パラメータ、とくに期間指定の形式）
- レスポンスがCSV本体か、生成後に別URLからダウンロードする形か
- 文字コード（Shift_JIS想定）

`Invoke-WebRequest -SessionVariable` でCookieを保持すれば、Windows標準のまま実装できる。

## 2. 携帯版Playwrightの作り方（事前準備・要インターネット）

**自分のWindows PCで1回だけ実行**して、USBにキットを作る。ホテル端末では何もインストールしない。

```powershell
# 例: USBドライブ E: に作る
.\Setup-PortablePlaywright.ps1 -KitPath E:\tl-kit
```

できあがる構成:

```
E:\tl-kit\
  node\            … 携帯版Node.js（インストーラ不要）
  browsers\        … Playwrightのブラウザ（PLAYWRIGHT_BROWSERS_PATH に指定）
  node_modules\
  export-tl.mjs    … 取得スクリプト（セレクタは selectors.json から読む）
  selectors.json   … 現地で埋める
  codegen.cmd      … 操作を記録してコードにする
  run.cmd          … 取得を実行する
```

現地での使い方:

```
E:\tl-kit\codegen.cmd https://<TLのURL>     ← 操作を記録してセレクタを拾う
（selectors.json を埋める）
E:\tl-kit\run.cmd                            ← 取得を実行（CSVが out\ に落ちる）
```

`run.cmd` は失敗するとスクリーンショットと trace を `out\` に残す。原因調査はそれを持ち帰って行う。

## 3. 無人実行（タスクスケジューラに登録するのは1本だけ）

```
powershell -ExecutionPolicy Bypass -File .\Invoke-Pipeline.ps1 `
  -KitPath C:\hotel-import\tl-kit -Endpoint https://api.example.com `
  -Email import@example.com -HotelId <hotelId> -Days 30
```

`Invoke-Pipeline.ps1` が「取得 → 送信」を続けて行い、どちらかが失敗すれば終了コード1で終わる
（スケジューラに失敗が残る）。取得が失敗したときは送信に進まない ―― 古いCSVを送って
成功に見せないため。`TL_USER` / `TL_PASSWORD` はタスクの実行ユーザー環境に設定しておく。

## 4. 取得後の流れ（既存）

```
CSV → Send-ReservationCsv.ps1 → POST /api/v1/import/reservations → DB → 画面
                                  ↑ 列マッピングはサーバ側に保存済み
```

日次バッチが「前日分が入っていない」「一定時間取込が成功していない」を検知してアラートを出す。
RPAは画面変更で黙って壊れるため、**この検知を有効にしてから常用に入る**。


## 5. エージェント型（browser-use / jev-ultrafast）を使う場合

[browser-use](https://browser-use.com/)（MIT・OSS）と [jev-ultrafast](https://github.com/browser-use/jev-ultrafast) を
現地で使う場合の前提。**クラウド実行は使えない**ので、ローカル実行の構成にする。

### 5-1. どこからTLへ通信が出るかだけが問題

TL-リンカーンにIP制限がある以上、判定はひとつ ―― **TLへのHTTP通信がホテル端末から出ているか**。
エージェント自体がどこで動くかは、それさえ満たせば自由。

| 形 | TLへの通信の出口 | 可否 | 必要なもの |
|----|---------------|------|-----------|
| **A. エージェントもブラウザもホテル端末** | ホテル端末 | ○ | 端末でPython(uv)が動くこと。USBの携帯構成で回避できる |
| **B. エージェントは自分のPC、ブラウザはホテル端末**（CDPリレー経由） | ホテル端末 | ○ | 端末で動かすのはUSBのNodeひとつだけ。ファイアウォールの受信許可が要る場合あり |
| **C. 自分のPCから画面共有・リモートデスクトップで端末を操作** | ホテル端末 | ○ | リモート接続の許可・有効化。DOMが取れずスクショ頼みになる |
| **D. browser-use Cloud / Codexのブラウザから直接TLへ** | 相手のクラウド | ✕ | ― |

つまり「**先方のPCを操作する**」形なら A・B・C のどれでも成立する。✕なのは D だけ。

用途で選ぶ:

- **決定論に落とす材料（セレクタ）が欲しい** → A か B（CDP経由でDOMが取れる）
- 端末で何も動かせない・時間がない → C（取れるのはスクショだけなので、`selectors.json` の材料としては弱い）
- **無人運用の本番** → 最終的にはホテル端末の中で完結させる（自分のPCが起動している前提には置けない）

### 5-1-b. B の構成（CDPリレー）

Chromeのデバッグポートは 127.0.0.1 からしか受け付けないので、同梱の `cdp-relay.mjs` で中継する。
Host ヘッダを `127.0.0.1:9222` に書き換えてから流すため、Chrome側のDNSリバインディング対策にも
引っかからない（Chromium 141 でHTTP取得とWebSocketアップグレードを確認済み）。

```powershell
# ホテル端末で
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 --user-data-dir="C:\hotel-import\chrome-profile"
E:\tl-kit\node\node.exe E:\tl-kit\cdp-relay.mjs --listen 9223 --target 9222

# 自分のPCから ws://<ホテル端末のIP>:9223 に接続してエージェントを動かす
```

注意:

- **デバッグポートに繋げた相手はブラウザを完全に操作できる。** LAN内で必要な時間だけ動かし、終わったら必ず止める
- Windowsのファイアウォールが受信を尋ねる場合がある（許可に管理者権限が要ることも）。通らなければ A に切り替える
- 探索用。無人運用には使わない

### 5-2. ローカル実行の構成

**すでに開いている Chrome に CDP で繋ぐ**のが要点。ログイン済みのセッションとホテルのIPをそのまま使えるので、
エージェントが自分でログインし直す必要がなく、MFAや同時ログイン制限の問題も避けやすい。

```powershell
# 1. Chromeをデバッグポート付きで起動（業務プロファイルと分けたいなら --user-data-dir も指定）
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 --user-data-dir="C:\hotel-import\chrome-profile"

# 2. 開いたChromeで手動でTL-リンカーンにログインしておく

# 3. エージェントを ws://127.0.0.1:9222 に接続して動かす
```

CDPは 127.0.0.1 からの接続しか受け付けない（Chromeの仕様）。**エージェントも同じ端末で動かす**必要がある。
ポートを外部に開けてはいけない（接続できる相手はブラウザを完全に操作できる）。

### 5-3. 端末に必要なもの（ここがハードル）

| 必要なもの | 備考 |
|-----------|------|
| Python（uv） | `uv` は単一実行ファイル。`UV_PYTHON_INSTALL_DIR` / `UV_CACHE_DIR` をUSB配下に向ければ携帯構成にできる。**事前に自分のPCで作って動作確認する** |
| Chrome | 端末に入っているものを使う（CDP接続なので追加インストール不要） |
| LLMのAPIキー | jev-ultrafast は `TYPESAFE_API_KEY` と `TEXT_MODEL_API_KEY`（OpenRouter等）の2つが要る |
| **外部LLM APIへの通信** | ここが塞がれていると動かない。自社APIへの到達性とは別に確認する |

jev-ultrafast は速い（Google Flightsの検索を7.1秒）が、**外部依存が2つに増える**。
まず browser-use 本体で1回通してから、速度が問題になったときに検討する。

### 5-4. 個人情報の扱い（先に合意しておく）

エージェントは**画面のDOMとスクリーンショットをLLMプロバイダに送る**。TL-リンカーンの予約一覧には
宿泊者名・連絡先が表示されるため、そのまま使うと個人情報が外部に出る。

- 可能なら、氏名・連絡先を表示しない検索条件・表示設定で操作する
- どのプロバイダに何が送られるかを、ホテル側に説明して合意を取る
- 合意が取れないうちは、エージェントは**手順の探索まで**にとどめ、本番運用は決定論的スクリプトで行う

### 5-5. 使い分け（重要）

| 用途 | 使うもの |
|------|---------|
| 初回の探索 ―― どの画面をどう操作すればCSVが落ちるかを見つける | **エージェント（browser-use）** |
| 毎日の取得 | **決定論的スクリプト**（`export-tl.mjs` + `selectors.json`、またはHARからのPowerShell再現） |
| 壊れたときの復旧 ―― 画面が変わってセレクタが効かなくなった | エージェントに原因を探らせ、`selectors.json` を直す |

日々の実行をエージェントに任せない理由: 1回ごとにモデル代がかかる、実行時間が読めない、
同じ操作でも毎回同じ経路を通る保証がない、失敗時に何が起きたか再現しづらい。
**販売中の在庫と料金を握る画面を毎日触る処理**としては、決定論的な方が安全。

### 5-6. 現地での順序（エージェント型）

1. Chrome をデバッグポート付きで起動し、手動でTLにログインしておく
2. エージェントに「予約検索を開き、直近30日を指定して、CSVをエクスポートする」を実行させる
   （指示文は `docs/ハンドオフ_取得自動化.md` §5 の禁止事項つきプロンプトを使う）
3. **エージェントの行動履歴（どの要素をどう操作したか）を必ず保存する** ―― これが `selectors.json` の材料
4. 落ちたCSVを `Inspect-ReservationCsv.ps1` で確認し、取込APIへ送る
5. 行動履歴から `selectors.json` を埋め、`run.cmd` で**エージェント無しで**同じことができるか確認する
6. できたらタスクスケジューラに登録（`Invoke-Pipeline.ps1`）

### 5-7. 事前に自分のPCで確かめておくこと

- `uv` の携帯構成（USB配下にPythonと依存を置いて動くか）
- browser-use が CDP 経由で既存Chromeに繋がるか（適当なサイトで1回動かす）
- APIキーの置き方（環境変数。スクリプトに書かない）
- 通信先のホスト名（現地で許可申請が必要になったときに即答できるように控えておく）

## 注意

- 操作は参照とエクスポートに限る。在庫・料金・プランの更新系には触らせない
- 認証情報はスクリプトに書かない（環境変数か、DPAPIで暗号化したファイル）
- HAR・trace・スクリーンショットにはセッショントークンや宿泊者名が入る。リポジトリにコミットしない
- 自動操作の規約上の扱いは別途確認する（シーナッツ社／ホテル）
